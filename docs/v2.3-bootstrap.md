### PDF boundary and regression scope

MIME type and extension are advisory only; valid `%PDF-` bytes are required before parser processing.

Issue #114 implements `requirePdfSignature` and `readPdfSourceBytes` in
`tools/shared/pdf.js`. File admission reads only `slice(0, 5)` before a full
read, then checks the returned buffer too. Cached-byte parser entry points use
the same primitive. The retained `isSupportedPdf` helper chooses an error
message only; file-picker accept attributes remain advisory UX hints.

The header must begin at byte zero, matching the first-line header specified in
[Adobe PDF Reference 1.7, section 3.4.1](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.7old.pdf).
Generated minimal fixtures and the existing real PDF corpus start there. BOMs,
junk preambles, empty files and incomplete prefixes are rejected; there is no
scan for a later header, even if a repair-tolerant parser could accept one.
A complete five-byte header passes admission only. It does not prove full PDF
validity: parser loading/page inspection remains the deeper rejection layer.

Audited original-source paths:

- Merge and Split use `loadPdfSource`; inspection uses the same loader.
- Organizer and Metadata use the loader and bounded reader; their exported
  cached-byte processing helpers explicitly require the signature again.
- PDF to Images uses inspection/bounded reading and `LocalPdfRenderer.load`.
- Organizer thumbnails also use `LocalPdfRenderer.load`, guarded before PDF.js.
- PDF to Text/Searchable PDF use `readPdfOcrSource`, the OCR service gate,
  the guarded renderer, and `createSearchablePdf` before pdf-lib loading.
- Metadata's second load verifies bytes freshly serialized by pdf-lib, rather
  than accepting another user input; original-source admission already ran.

`tests/pdf-signature.test.mjs` covers real PDF admission/merge/split with normal,
empty and misleading MIME/name metadata; spoofed bytes, empty/truncated prefixes,
BOM/preambles, typed-array offsets, bounded reads, swapped adapter bytes,
cached-byte/OCR/renderer rejection before parsing, and malformed complete headers
rejected by pdf-lib. Existing OCR/cancellation fixtures now contain complete
headers so those tests still reach their intended paths. Existing render bounds
(16,384 dimension, 50 million pixels), large-page warning, cancellation and
resource cleanup are unchanged. F-01 is resolved by this implementation; its PR
still requires review and integration before release.

### Hosting-layer HTTP headers — Issue #117

The source of truth is `config/cloudflare/_headers`. `build-site.mjs` copies
it into `dist/_headers`; the isolated Cloudflare bridge copies it unchanged and
removes only that artifact's legacy CNAME. Generic/GitHub Pages ownership remains
unchanged. The workflow no longer overwrites the policy with alias-only headers.
[Cloudflare Pages header rules](https://developers.cloudflare.com/pages/configuration/headers/)
apply to static responses; matching rules combine headers, and redirects execute
first. No Functions/advanced Worker is introduced.

The global policy enforces:

- CSP: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' blob: data:; font-src 'self'; worker-src 'self'; connect-src 'none'; object-src 'none'; frame-src 'none'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`.
- `Referrer-Policy: no-referrer`.
- `Permissions-Policy: camera=(), microphone=(), geolocation=()` (unused sensitive capabilities).
- `X-Content-Type-Options: nosniff`.

The original HTML meta policies remain. Image Blob/data sources support local
previews; fonts and worker entry points remain same-origin. HTTP
`frame-ancestors 'none'` provides the embedding boundary that meta CSP cannot.
No inline/eval exception, external origin, cache/MIME override, reporting endpoint,
analytics or telemetry is added. Alias-only noindex rules remain separate, so
`tools.securetools.app` stays indexable.

Only `/assets/vendor/tesseract/worker/worker.min.js` detaches the global CSP.
This preserves the existing dedicated worker context: its vendored code loads
same-origin core/WASM/traineddata, and `workerBlobURL: false` remains in place.
[Workers use their script response policy](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy#csp_in_workers);
applying document connect-src none and script-src self there would break existing
OCR asset fetching/WASM compilation. This exception does not remove any previous
worker CSP (there was none) or relax the document's connection policy. The worker's
own network boundary remains trusted pinned vendor code plus browser request
verification, not a new restrictive worker CSP. PDF.js retains the global policy
and its disabled evaluation/worker fetching/WASM settings. This task does not
redesign the application/worker CSP model.

`scripts/http-security-headers.mjs` validates the reviewed policy, its exact
worker exception, alias isolation and isolated CNAME absence. `validate-build.mjs`
requires it for every build. Security regressions reject missing/weak CSP,
connections, embedding protection, inline/eval/external origins, privacy headers,
and widened exceptions. The artifact HTTP server reads this same configuration;
release tests verify all canonical HTML/linked assets and JSON/WASM/worker/lang
MIME types. Live response validation permits extra capability denials, but requires
camera/microphone/geolocation to be denied; the source policy remains exactly the
reviewed three denials.

Deployment smoke and the full production smoke now check real response headers
on representative canonical/immutable routes, worker scripts and build-info.json.
CI runs the existing complete OCR/searchable-PDF/native-download/privacy browser
gate against the local built artifact in a clean GitHub environment. This is
artifact compatibility evidence, not proof of Cloudflare serving behavior.

Read-only baseline on 2026-10-09: canonical root/PDF-to-Text and immutable root
still have no HTTP CSP/Permissions-Policy; Referrer-Policy is
strict-origin-when-cross-origin and nosniff is present. Canonical build-info.json
still returns 404 HTML. No production deployment or dashboard change occurred.
A local browser run exercised OCR/PDF workers/WASM/fonts, native downloads and
cancellation successfully; its clean privacy signoff failed because this computer's
AdGuard injected external scripts and rewrote HTTP CSP. Local full HTTP tests
therefore fail closed on the transformed policy. The strict gate remains intact; clean hosted
CI evidence is required. F-05 remains PARTIALLY RESOLVED until an authorized
release verifies actual canonical/immutable responses and clean browser behavior.
Cloudflare static delivery/project configuration is still a trust boundary;
Functions, hosting transformations or future path changes require renewed checks.

## Issue #112 provenance implementation (pending integration/promotion)

The refreshed provenance branch incorporates the reviewed bootstrap policy from

F-06 remains **PARTIALLY RESOLVED**. The implementation is verified locally/in CI,
but is not yet deployed on production. No end-to-end production claim is made.

The generated artifact contains `dist/build-info.json`; its public path after
production promotion will be `/build-info.json`. Schema 1 contains exactly
`schemaVersion`, `commit`, `version`, and `build: { source }`. The source marker is
`github-actions` in GitHub Actions, otherwise `local`; no timestamps, usernames,
paths, runner IDs, secrets, branches, or deployment URLs are exposed. It is generated
in `dist`, not tracked in source. Identical inputs produce identical record bytes.

The build takes full lowercase 40-character `GITHUB_SHA` directly. CI rejects
missing/invalid input and never falls back to Git. Local builds without that input
use Git HEAD and are explicitly marked local; local working-tree content is not
certified by that record. Existing build tooling uses Node `.mjs`, which is reused.
`version` reads the existing `package.json` version, currently `0.0.0`; it is not
relabelled as v2.2.0 and no second manual version constant is introduced.

`scripts/validate-build.mjs` requires the record and compares its strict schema,
SHA, version, and marker to the build context. CI invokes it after the production
build. Isolated bridge packaging preserves the exact JSON while removing CNAME;
tests execute the actual packaging block. The same directory is handed to Wrangler.
Production push/dispatch checkout uses the workflow source commit and automatic
`GITHUB_SHA`; PR CI uses its GitHub-generated test merge SHA, never presented as a
production release.

`scripts/verify-build-provenance.mjs` requires HTTP 200 JSON without redirects and
checks the deployed record against the explicit expected SHA and canonical package
version. Deployment runs it on the immutable URL and both stable aliases with
the existing alias retries. The manual production smoke accepts `source_commit`,
checks out that exact source/version, and checks both origins, recording the result
in its report. Use verification workflow code from this implementation or later;
old releases do not contain the new gate.

The current v2.2.0 production deployment lacks this generated record and was not
redeployed for this issue. A 2026-10-07 read of `/build-info.json` returned HTTP 404
HTML on both canonical and immutable production origins. Future release signoff must verify the newly promoted
source SHA on both origins before considering F-06 resolved within this bounded
model. Remaining trust: GitHub builds/checkouts and Cloudflare serving are trusted;
a record is not a signature or proof that every served byte came from that commit.
This change adds no full file-hash manifest, reproducibility proof, SLSA claim,
account-compromise protection, runtime fetch, UI, or telemetry. Existing sampled
asset equivalence checks remain in place. Full digest/attestation work is a
separate decision rather than an implicit guarantee of this compact record.
