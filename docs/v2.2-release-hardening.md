### Capture mechanism and native limitation

The opt-in `--gates` test server captures the exact immutable Blob at the actual `HTMLAnchorElement.click()` download boundary. The real visible public export control is clicked through browser automation; export helpers are never directly invoked for this evidence. The tracer associates filename, source, route, explicit UI action sequence, byte count, URL creation/click/capture/revocation times, and capture completion. It copies `blob.arrayBuffer()` before revocation, preserves the native anchor click, and publishes bytes only into test-page DOM evidence. Captured bytes are saved locally with SHA-256 and parsed independently. There is no production debug API, telemetry, external request, or CSP weakening.

This is **Level B completed browser-boundary artifact capture**, not DOM-only anchor intent and not a claim of native file completion. A native download listener was again registered before the first public action and timed out after five seconds while Level B completed successfully. Previously one native public English file and a static HTTP control download were captured; native blob event/completion reporting remains inconsistent.

Root-cause conclusion: byte generation and actual browser-boundary consumption are correct; the observed remaining limitation lies in native blob download completion/event observation in this environment. The test cannot distinguish browser internals from automation-wrapper reporting conclusively. Every Level B copy completed before normal revocation, and earlier 30-second URL-retention diagnostics did not repair native reporting. Premature product revocation is not supported by the evidence; product runtime is unchanged. The task explicitly accepts Level B, so this native-only coverage limitation is non-blocking.
