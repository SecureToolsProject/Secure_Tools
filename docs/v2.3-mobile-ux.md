# Mobile UX pass — Issue #128

This development pass follows the PR #127 normal merge into `v2.3` at
`91e89a70fe37452b3e2b767135a387f400f04436`. It does not promote production
or close the security audit's outstanding activation/coverage/live-delivery limits.

## Shared UI inventory and decisions

- The 19 canonical pages and 404 page repeat one header structure. Navigation
  and language/theme controls now share one native `details` disclosure, with
  a translated Menu summary in all six catalogs. No duplicate controls or IDs.
  Without JavaScript it remains a working disclosure at every width. With JS,
  desktop/tablet navigation is open and the summary hidden above 38rem; mobile
  starts closed. Enter/Space and expanded semantics are native, Escape returns
  focus to the summary, and there is no modal or focus trap. Crossing the
  breakpoint resets the disclosure and preserves a visible keyboard focus.
- All category/tool pages use `.category-nav__inner`. Mobile reduces padding
  to `--space-1`, keeps a single scrollable row and 44px link targets, and
  retains `aria-current`. Neither header nor categories become sticky.
- Inspected `base`, `components`, `pages`, `categories`, shared tool CSS and all
  eleven per-tool stylesheets. Existing layout breakpoints span 24, 30, 38,
  42, 44, 46, 48, 52, 54, 56 and 68rem; this pass retains existing desktop and
  tool grid breakpoints. Shared mobile workspace/section gaps use `--space-6`
  instead of scattered child margins. Metadata cards/results/limitations and
  status spacing use the same tokens; desktop gaps remain unchanged.
- Both metadata scope asides move in actual document order after the cleaning
  result/comparison and before the existing polite live status. All scope text,
  localized keys, heading IDs and supported/unsupported claims are retained.
  Shared typography/padding removes the large heading/accent-bar treatment;
  limitations remain visible, without an extra disclosure.
- The inherited font reset previously reset body/controls to the root's browser
  default. Root font-family now establishes the existing intended system font.
  Removing the body's 320px minimum avoids overflow when a classic scrollbar
  reduces the available content width at a 320px viewport.

### Select inventory

Every production header has language and theme selects. Tool-specific selects:

| Tool | Native selects |
| --- | --- |
| Image Converter, Resize, Compressor | Output format |
| Image to Text, PDF to Text | OCR language |
| Images to PDF | Page size, orientation, fit, quality |
| PDF to Images | Image format, render scale |
| Metadata, PDF Merge/Split/Organizer | Global preference selects only |

Resize dimensions/compression quality use existing inputs/radio/range controls;
these do not need dropdown adapters. The retired `/tools/privacy/` source is
not a canonical built page; its URL is a permanent redirect to `/privacy/`.

**Strategy: enhanced native selects.** Shared appearance, CSS arrow, option
palette, resolved `color-scheme`, focus and disabled treatment cover all selects.
Fine-pointer desktop browsers supporting `appearance: base-select` also receive
a themed native picker with selected/hover/focus states. Other browsers retain
native options and apply supported colors; mobile keeps its platform picker.
Forced-colors restores the native appearance. No custom ARIA listbox, library,
portal, script-based option rendering or new runtime dependency is introduced.

This deliberately preserves platform keyboard, typeahead, touch and assistive
technology behavior. Complete identical OS popup rendering is not promised.
See [MDN's native select customization](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Customizable_select)
and [option styling limits](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/option).

## Reproducible verification

`node tests/browser/responsive.mjs` uses the real built artifact/server and
strict hosting-header validation. It covers 441 combinations: seven viewports
(320×568, 360×800, 375×812, 390×844, 430×932, 768×1024, 1280×900), seven routes
(home, Image category, Converter, Image OCR, PDF Merge, both Metadata tools),
EN/KO/JA, and System/Light/Dark. It checks compact height, native disclosure tab
order/Escape, current/single-row categories, overflow/control bounds, heading/skip
targets, scope order, long CJK PDF metadata and real metadata-clean downloads.
It also checks system theme changes, native select keyboard selection, and no-JS
navigation. Existing full i18n checks cover all six catalogs. Diagnostics and
screenshots are written under `.ts-build/responsive` and retained on CI failure.

Local pinned install, build/artifact validation, real English/Korean/combined OCR,
fresh lockfile/vendor advisories and structural tests passed. Local full tests
reach the strict HTTP gate and fail closed because installed AdGuard rewrites
CSP to allow `local.adguard.org`, changes `connect-src`, and injects scripts.
No expected policy, network assertion or app CSP is relaxed for that environment.
Clean GitHub CI is required for the complete HTTP/browser/security result.

The review PR records final CI evidence. A physical iOS/Android picker and a
screen reader on each OS remain useful manual follow-up; browser emulation and
semantic/keyboard checks do not claim to replace those device/AT combinations.
